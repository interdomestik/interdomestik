## The replay of R3, and what it changed in this file

The R2 drafts, as corrected before the replay (`A/raw/R3/replay/drafts/`, frozen on 2026-11-17 at 11:40Z), were tested on twelve cases that a curator had sealed before any rule was drafted: eight merged defects of eight classes, and four sound changes as controls. **This is inferred rule coverage on twelve cases, not proven prevention.** The reviewer knew the symptom of every case; a reviewer before a merge does not. No check was executed. Twelve cases cannot show that a rule works, and a rule that did not fire is not shown to be useless. Both misses are defects that the reviewer saw and did not flag because no rule covered them: they measure the rules, not the reviewer. The score describes the drafts as frozen; nothing that the table below lists as revised inherits it. Two more limits of how the replay was run (added in the closing pass, review comment R3-C11): the reviewer and the grader ran on the same model (Opus 5.5 at high effort), each with a context of its own, so the grading is independent by context and not by model; and after the grading the main session read the grader's case-level report, because the revision needs the misses, so every rule text written after 12:16Z of that day was written with knowledge of the sealed cases. Neither changes a score. What was scored is the set frozen at 11:40Z, the R2 drafts with the corrections made before the replay, and nothing written later: not the revisions below, not the fixes after the drill, not the changes for the adoption, not the changes of the closing pass (R-37 among them), not those of the delta fix round or of the final round of 2026-11-18.

**What the replay says about the checks.** No detection was mechanical. Three checks were the nearest fit and would have let the defect pass, each for a stated reason: a baseline that holds today's code, a predicate about new write sites, a list of names. A check with a baseline protects new code; code on the baseline is protected only when the list shrinks. `CI-GATE-PROPOSALS.md` 4.1 therefore adds that a change which touches a file on a baseline is told so in the PR, and that the review record says whether the entry was fixed.
