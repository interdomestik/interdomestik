# Recipe 2 — The correspondence register for insurers and bureaus (in the pilot)

Planned statically at `ef1bd0ef5`; the helper opened every `path:line` it cites. No code written, nothing run.
Feature source: `DIRECTION.md:286-296` (WP-12), business rule 4.

## 1. Scope in five lines
Staff on a Green Card case record every exchange with an insurer, bureau or other outside party: who sent it and under what authorization, which documents were shared, what came back, when to follow up (OBSERVED `DIRECTION.md:292`).
Never: give the outside party an account, session or read path into the case (R-17, `AGENTS.md`); copy a shared document into a second row or bucket (R-35); decide coverage or compensation (`DIRECTION.md:290`).

## 2. Module contract first (R-19)
Owner: `packages/domain-claims` — it owns the claim support tables (OBSERVED `packages/domain-claims/MODULE.md:13-15`); one owner, one command set (R-16). Documents stay with `packages/domain-documents` (`apps/web/src/lib/storage/MODULE.md:13-15`): the register references, never writes a document row.

New table `claim_correspondence`, modelled column-for-column on `claim_information_requests` (`packages/database/src/schema/claim-information-requests.ts:35-100`): `id`; `tenant_id` not null FK `tenants`; `claim_id` not null FK `claims`; `correlation_id` (idempotency); `direction` (`outbound`|`inbound`); the outside party as `party_kind` (`insurer`|`bureau`|`other`), `party_organisation`, `party_reference`, `channel` and an optional `party_contact_name`, which is deleted with the case (owner, answer 31); `authority_id`, set on every outbound record: the legal basis, as a reference to the case's authority (one reference in this plan; if an action of the pilot needs two bases together, WP-12 adds a second reference or a link table before the table is created: closing pass, review comment R3-C04; next paragraph; the R2b plan kept the basis in four columns of this row, which can show an expiry and cannot show a revocation); `sent_by_staff_id` / `recorded_by_staff_id` FK `user`; `share_pack_id` FK `share_packs` nullable; `body`; `answered_at`; `answer_summary`; `follow_up_at`; `created_at`.
A second new table, the authorities of a case (`claim_authorities`; found necessary by the drill of R3): `id`; `tenant_id`; `claim_id`; `kind`, one of four values (`recovery_agreement`, `power_of_attorney`, `signed_assignment`, `consent_or_lawful_basis`); `reference` — for a recovery agreement the id of its row in `claim_escalation_agreements` (`packages/database/src/schema/claim-commercial.ts:30-89`, which holds the terms version and the signed and accepted times and neither an expiry nor a revocation), otherwise the document that proves the authority; `version`; `scope`; `granted_at`; `expires_at`, nullable; `revoked_at` and `revoked_by_user_id`, nullable; `recorded_by_staff_id`; `created_at`; composite unique `(tenant_id, claim_id, id)`; the same tenant policy. The register's `authority_id` is a composite foreign key `(tenant_id, claim_id, authority_id)` to it, so a record can cite only an authority of its own claim. Three of the four kinds have no table today.
Tenant policy: the `pgPolicy` shape of `claim-information-requests.ts:96-100` — `using` the tenant GUC, `withCheck` additionally proving the claim is of that tenant (`:93-99`).
Constraints: composite unique `(tenant_id, claim_id, id)` (model `:66-70`); correlation unique (`:62-65`); non-empty-text CHECK (`:76-79`); a CHECK that `answered_at` and `answer_summary` are both set or both null (model, the posture CHECK `:80-87`); a composite FK `(tenant_id, share_pack_id)` → `share_packs`, so a pack of another tenant cannot be cited (model `drizzle/0094_request_linked_evidence.sql:20-21`). **That key needs a unique parent key, and none exists** (review comment R2b-C10): `share_packs` has the primary key `id` and two non-unique indexes (`packages/database/src/schema/documents.ts:108-139`). The migration therefore first adds a unique index on `share_packs (tenant_id, id)` — as `0094` did for its own two parent tables at `:16-17` — and only then the foreign key. With `id` already unique, the new index cannot fail on existing rows (`INFERRED` from the constraint; nothing was executed).
Commands: `recordOutboundCorrespondence`, `recordInboundAnswer`, `listClaimCorrespondence`, `setCorrespondenceFollowUp`, each `(session, authority, input)` in one `withTenantAuthority`, like `createInformationRequest` (`packages/domain-claims/src/claims/information-requests.ts:40-70`). Two more for the authorities, `recordCaseAuthority` and `revokeCaseAuthority`, in a file of their own: the model file has 231 lines, and the size guard fails a new source file above 300 (`scripts/modularity-guard-policy.mjs:2`). The recording commands admit the assigned staff member — the check of the model, which reads the claim row under a lock (`information-requests.ts:55-64`) — and the administrator roles; every other role that can open the case reads through `listClaimCorrespondence` only, and a branch manager gets counts and dates, not content (owner, answers 31 and 27 c). An outbound record is refused when its authority is revoked or expired. **A condition inside the insert is not enough for that** (closing pass, review comment R3-C03): an insert that selects from the authority row can read it as valid while `revokeCaseAuthority` commits, and a foreign key does not put the two in an order. The synchronization is designed in WP-12 and is one of its acceptance criteria (`DIRECTION.md`, WP-12): one protocol that the recording and the revoking command both use — a lock on the authority row, or the lock on the claim row that the model already takes (`information-requests.ts:55-64`), taken by both in the same order — the moment at which the authorization is decided, scope and expiry checked again at that moment, and a test on two connections that shows both orders. A revocation sets a time; the earlier records stay. The follow-up time is an instant with an offset, like `dueAt` of the model (`information-requests.ts:32`).
**R-17 / DATA-13:** `createSharePack` opens its own `withTenantAuthority` (`apps/web/src/features/share-pack/share-pack.service.ts:134-140`), so the command must not call it inside its own transaction. Build the pack first and pass the id in, or add a `tx`-taking variant — `canShareAllDocuments` already takes a `tx` (`:135`), which is the house shape. The command cannot import that service, because a package does not import the application. The documents package therefore gets one small query, `packages/domain-documents/src/share-packs.ts`, that takes the caller's transaction and resolves a pack for one case — the tenant, the entity type `claim`, the entity id, not revoked, not expired (`packages/database/src/schema/documents.ts:108-139`: the entity is two text columns, so no foreign key can say it) — and the command calls it before it stores the pack id (R-16; drill gap G06).

## 8. Gaps the plan met
1. **A dormant half-register exists and is not reused** (an engineering choice, decided in the module contract). `claim_threads` has the insurer fields and no runtime caller (MEASURED, §4). The register gets its own table. Reusing the thread table would not have required its duplicate message declaration; the R2b text was wrong to say so (review comment R2b-C11).
2. **Owner of the new table: `domain-claims`** (decided in its module contract, R3). The register cites a share pack, which the documents area owns, and writes no document row.
3. **Reference without a second copy: the stored list is kept** (an engineering choice, decided). `share_packs.documentIds` is a stored column, separate from `expiresAt` and `revokedAt` (`documents.ts:126-132`). Expiry and revocation stop the public link — the reader filters them (`apps/web/src/features/share-pack/share-pack.service.ts:166-177`) — and erase nothing. The R2b text said that the fact "dies with the pack"; it does not (review comment R2b-C11). The register cites the pack id, and a cited pack is not deleted before the case's retention ends.
4. **Follow-up: the staff list only, no reminder** (WP-12's own "Done when"; a decision of scope, not an open question). The read-time pattern `assigned-claim-attention.ts:16-19,44-45` satisfies it without a job. A notification would be new scope and would fall under R-11.
5. **Who records: the assigned staff member and the administrators; every other role reads** (owner, 2026-11-17, answer 31). The model command admits `staff` only and requires the assigned staff member (`information-requests.ts:46-48,64`); the new commands add the administrator roles. The pilot has no branch manager, and by answer 27 c a branch manager sees no content.
6. **The outside party: the organisation, its reference and the channel; a named contact person may be stored, is kept for the case's retention period and is deleted with the case** (owner, answer 31). No party directory exists (MEASURED as before) and none is built: the fields live on the register's row. The retention job itself does not exist yet (POPS-06, WP-13).
7. **The authorization basis is one of four** (owner, answer 31: the list of the requirements baseline, checked by the business's lawyer, used as given): an accepted, versioned recovery agreement (IDA-REC-003; IDA-SVC-014); an active, case-specific, jurisdiction-appropriate power of attorney or equivalent authority (IDA-REC-004), where a revoked or expired authority blocks new actions at once and keeps the history (IDA-REC-005); a signed assignment (PRC-32); versioned purpose-specific consent, or lawful-basis evidence (IDA-DOC-012). Each recorded basis carries its scope and its expiry; the field is an enumeration, not free text. Re-read in R3 in the pilot subset of the requirements: IDA-REC-003, -004 and -005 (`A/srs-pilot-subset.md:265-267`), which say what the owner input says; IDA-SVC-014 and the row of PRC-32 are not in the subset; they were read in the English baseline in the closing pass, with IDA-DOC-012, which the subset holds (`inputs/srs-v0.9.docx`, text extract lines 4552-4553, 925-929 and 5092-5093). **One value does not discharge what an action needs** (closing pass, review comment R3-C04): the enumeration classifies the evidence, and the baseline joins bases for some actions — "Service 2 shall not contact an insurer, authority, lawyer, expert, or counterparty on behalf of the user without the separately required agreement and authority" (IDA-SVC-014); "Accepted fee disclosure plus signed assignment or valid POA" (PRC-32). Which bases, in which scope and jurisdiction, each outward action of the pilot needs is fixed in the acceptance of WP-12, and the recording command then checks the kinds, the scope and the expiry that the action requires, not only that an authority is cited. Professional recovery and VONESA are outside the pilot by the business owner's decision, so which of the four the pilot's cases carry is the business's matter; the enumeration holds all four.
8. **The nearest model violates R-05** (`information-request.ts:22-29`, §4). An agent told to "follow the existing pattern" reproduces the violation, so the recipe must state the wrapper explicitly.
9. **The four legal bases had no home** (drill gap G04; decided in the module contract as an engineering choice, offered to the owner). "A revoked or expired basis refuses a new outbound record" needs a row that can be revoked. Only the recovery agreement has a table, and that table has neither an expiry nor a revocation (`claim-commercial.ts:30-89`). The plan gains the table of a case's authorities and two commands; the register cites an authority instead of carrying four columns.
10. **A domain command cannot reach the share-pack service** (drill gap G06). The service lives in the application; the documents package exports no share-pack query (`packages/domain-documents/package.json:7-12`). The plan gains one query in that package.
