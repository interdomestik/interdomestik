## CTX-006 logical mapping

### Identity, credentials and linked sign-in identities

- **Authority:** Better Auth via the declared server adapter; records persisted in Supabase PostgreSQL
- **Direction:** Application authentication commands enter through shared-auth and the declared adapter; consumers receive a minimal authenticated identity projection. No synchronization or dual-write authority to Supabase Auth is admitted.
- **Conflict:** Fail closed on ambiguous identity/linkage or conflicting authority; no client-supplied tenant/role inference and no automatic merge of credentials. Apply the existing approved identity-link/recovery contracts.
- **Reconciliation owner:** Platform identity-boundary owner; Security reviews identity/recovery exceptions. Named implementation/operating assignee is bound during authorized delivery.
- **Failure behavior:** Authentication failure yields no newly authenticated authority; preserve existing explicit retry/recovery and audit contracts without revealing another account.
- **Limit:** Logical responsibility mapping only. A shared physical user row does not transfer role, membership or business-field ownership to Better Auth.

### Sessions, credential-bound session lifecycle and assurance

- **Authority:** Better Auth via the declared server adapter; shared-auth supplies the application contract
- **Direction:** Create, validate, rotate, revoke and reauthenticate through the single owner; proxy/action/resource checks consume current session assertions and independently derive applicable authorization. No second session issuer or Supabase Auth session synchronization.
- **Conflict:** Reject stale, ambiguous, expired, revoked or unapproved-owner session assertions. Transitional adapters/exceptions may not introduce another owner.
- **Reconciliation owner:** Platform identity-boundary owner with Security acceptance of lifecycle and privileged-access evidence.
- **Failure behavior:** Fail closed; no credential/session bypass or fallback to an unapproved owner. Preserve bounded retry behavior without converting an unresolved assertion into access.
- **Limit:** Preserves IAM-011 MFA, IAM-012 cookies/lifetime/rotation/revocation/reauthentication and the observed proxy/cache acceptance obligations; does not assert they are implemented.

### Tenant/branch/role, grants, assignments, membership and business entitlements

- **Authority:** Existing application/domain authority and tenant/RLS boundaries, not the identity provider
- **Direction:** Server-derived identity is an input to current application authorization; no inbound provider claim automatically grants business privilege. Existing governed writers retain their responsibilities.
- **Conflict:** Current scoped authority and sole-writer invariants prevail; deny unresolved scope or stale/revoked grant.
- **Reconciliation owner:** Existing domain authority owners; Platform and Security own identity-to-authorization boundary integration.
- **Failure behavior:** Deny the affected business action without unauthorized mutation or disclosure.
- **Limit:** Included to prevent the identity amendment from silently expanding Better Auth ownership; no domain rewrite or new schema is proposed.
