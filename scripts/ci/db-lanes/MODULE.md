# Database test lanes

Run `node scripts/ci/db-lanes/inventory.mjs` from the repository to print the tracked file inventory. CI reads the same inventory before launching the advisory tests. Stage new tests before checking their selection locally.

The inventory records the explicit RLS and journal parity selectors in `ci.yml` and their runners on broad CI. For database-mocked suites without conditional test gates, it lists files using the Vitest projects and selectors from the coverage command, which runs when CI cannot reuse coverage. These entries describe selection. On broad pull requests, the Database Lanes workflow reports its execution by file and counts passing, failed, skipped, TODO, cancelled, and retried cases. Its orphan check and lane outcomes are advisory until admitted under R-10 with owner approval.

The advisory job runs database-package TypeScript tests with Node. Top-level tests run without a database unless they use a live fixture or a database test suffix. Nested tests under `packages/database/test/pg16/` run on the job's loopback-only, journal-built PG16 service. Use `.rls.test.ts`, `.postgres.test.ts`, `.pg16.test.ts`, or `.integration.test.ts` for new database suites in `apps/web/src/` or `packages/domain-*/src/`. These suites run with the owning project's Vitest configuration. Discovery also detects RLS specs, auth contracts, and script tests that opt into a live database. Use the existing fixture appropriate to the suite and assert the effective role where required. Each exclusion specifies the file, reason, owner, and removal condition.
