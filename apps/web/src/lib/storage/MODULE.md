## Responsibility

Builds and asserts every storage path, holds the two private buckets behind a service-role client, decides who may upload and who may download a document row, and records the access.

## Invariants

- A storage path is server-built and asserted before every privileged call — enforced: paths are built on the server from tenant, actor or claim, a generated file id and a sanitised name, then re-asserted to `pii/tenants/<tenant>/<family>/…` with traversal rejection before each of the 6 service-role calls (`lib/storage/tenant-prefix.ts:29-88`; `lib/storage/service-role.ts:88-158`; `app/api/uploads/_core.ts:107-153`; `A/modules/tenancy.md:234`). The assertion runs first in every call (`service-role.ts:88`); in the deterministic storage mode of the E2E runs (`:41-43`, `:90-92`) no storage client is built after it.
- The storage barrier is **application-level only**. The declared storage row policies target the provider's `authenticated` role via `auth.uid()`, but the application authenticates with Better Auth and reaches storage only through the service-role client, so those policies are **not on the application path**; both buckets are private (`A/modules/tenancy.md:133,140`; `supabase/migrations/00009_storage_tenant_prefix_backstop.sql:43-151`). Those storage SQL files are applied by **no workflow** (`docs/engineering/DB-BASELINE.md:122`), so even the backstop is not built.
- A storage path is used by one document — database unique (`packages/database/src/schema/documents.ts:74`).
- A polymorphic document points at an existing entity of the same tenant — **NOT ENFORCED**: `entity_type` + `entity_id`, no FK (`schema/documents.ts:43-44`).
- The document access log is append-only — **NOT ENFORCED**: a comment only, no trigger and no privilege restriction (`schema/documents.ts:78-105`; `A/modules/data-layer.md:133`).
- An upload is bound to its requester — enforced: an HMAC-SHA256 intent token over actor, tenant, bucket, file id, size, MIME type and path, 15 minutes, constant-time compare (`initial-claim-upload.ts:5,68-141`, cited by `A/modules/case-handoff.md:198`); content type and size are checked on request, again at submit against name and path, and then the stored object and its content are validated.
- Claim evidence is never overwritten — enforced inside one of the two upload functions, and by the callers of the other (corrected in the closing pass, review comment R3-C05). `createTenantSignedUploadUrl` sets the overwrite option to false for the family `claims`, whatever its caller passes (`lib/storage/service-role.ts:82-97`). `uploadTenantObject` passes on what its caller gives, and false when nothing is given (`:118-127`); its three callers, the direct evidence upload among them, pass `upsert: false` (`app/api/claims/evidence-upload/_upload.ts:56-65`, `app/api/policies/analyze/_services.ts:81-90`, `actions/uploads/voice-note-storage.ts:127-132`). A new caller that passed `true` for a claim path would not be stopped by the function; whether a guard would refuse it is `UNVERIFIED`. The upload route also passes `upsert: false` (`app/api/uploads/_core.ts:146-153`).
- A signed URL is short-lived — **partly**: downloads are 300 s (`A/modules/case-handoff.md:201`), but the **upload** response says 300 s while no expiry is passed to the storage call (`app/api/uploads/_core.ts:177`; `service-role.ts:96`) — UNVERIFIED, lead CASE-L1.
- A staff page receives the download route, not a storage path or a signed URL — observed for the documents of an assigned claim (`get-assigned-claim-documents.ts:24-27,96-102`); other staff surfaces were not traced, so "never" is not shown.
- A file is removed when its retention ends — **NOT ENFORCED**: no retention period and no job for pilot data; files are never removed from storage (POPS-06, `packages/domain-documents/src/document-lifecycle.ts:15-18`).
- AI-extraction consent can be withdrawn — **NOT ENFORCED**: it can be given but not withdrawn (POPS-09, `apps/web/src/features/claims/upload/server/claim-document-write.ts:224-233`).

## Tenant boundary

Download runs in a tenant-bound transaction and admits full-tenant roles, the owner, the uploader, staff only when `staffId` = self, the agent scope and a case grant, and never staff on a draft (`app/api/documents/_core.ts:125-169`; `claim-document-access.ts:82-102`). Upload authorization: member roles with the tenant from the session authority when no claim exists yet; otherwise the claim must match the access tenant (`app/api/uploads/_core.ts:57-83`); staff and admin go through a separate predicate (`features/claims/upload/server/access.ts:20-52`). R1 ruled download and upload out as bypass paths and found **no** cross-tenant or cross-member reachability in the files it read (`A/modules/tenancy.md:158-159`; `A/modules/case-handoff.md:206`). **Left open:** the signed-URL route `app/api/documents/[id]/route.ts`, `app/api/claims/evidence-upload/**` and `app/api/policies/analyze/**` were **not read** (`A/modules/tenancy.md:163`); the cross-tenant grant fallback and the agent document scope were not opened either. The CI tenant guards cannot see storage paths at all (TEN-04, `A/modules/tenancy.md:185`).

## Live and not live

Live: member and staff evidence upload, the download route, the access decision, the intent token, the 300 s download URL. Live but not on a reviewed path: the cross-tenant case-grant document lookup runs on every document miss and **has no production writer of grants** (TEN-03, `app/api/documents/cross-tenant-document-lookup.ts:131-147`). Not live: no retention or deletion job (POPS-06); no data-subject export (POPS-02); a deletion request is stored and **nothing can act on it** (POPS-01, S2, `app/api/privacy/data-deletion/_core.ts:118-145`) — and that route has no rate limiter (`A/modules/security.md:47`).
